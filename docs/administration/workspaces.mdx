---
title: "Workspaces"
description: "Create, rename, and manage workspace-level isolation inside an organization."
---

A **workspace** is RunLedger's primary isolation boundary inside an organization. Runs, sessions, API keys, budgets, cache entries, gateway requests, outcomes, and audit events are scoped to a workspace.

## Who Can Manage Workspaces

- Org admins and org managers can create and rename workspaces inside their organization.
- Platform admins can do the same when operating inside an organization.
- Workspace admins can manage controls for their active workspace, but they cannot create or rename workspaces.
- Members have read-only visibility into their assigned workspaces.

## Common Actions

- Create a workspace for a new operating group or workload boundary.
- Rename a workspace from the Workspace page.
- Add members and set workspace roles.
- Switch workspaces from the top bar.

After a workspace rename, the dashboard session updates `workspace_name`, so the top bar breadcrumb changes immediately.

## Workspace Admin Scope

Workspace admins can operate within their active workspace:

- Create and revoke workspace-scoped API keys.
- Create, edit, and delete budgets.
- View Outcomes & ROI.
- Review Approvals and Audit Log.

Workspace admins do not see org-level Gateway, Provider Profiles, Alert Rules, MCP, Onboarding setup surfaces, Data Capture, Org Profile, Users, Workspace creation, or platform Settings.

## Observe and FinOps Integration

- `GET /analytics/workspace-observe-posture` returns a 30-day workspace summary: run count, total cost, tokens, active users, model count, error count, and FinOps coverage (budgets, billing periods, budget notifications).
- The Workspace page links directly to key Observe surfaces (Sessions, Model Usage, Economics, Cost & Savings, Analytics Users, Engineering, Monitoring, Request Flow) and FinOps surfaces (Billing Summary, Outcomes & ROI, Budgets, Billing Periods, Ledger).

## Cross-Feature Relationships

| Surface | Relationship |
|---------|-------------|
| Sessions, Run detail | Workspace-scoped session and run investigation |
| Model usage, Analytics | Workspace-scoped cost attribution and model breakdown |
| Cost & Savings, Economics | Workspace-scoped savings and economic analysis |
| Engineering, Monitoring | Workspace-scoped operational metrics and alerting |
| Request flow, Request explorer | Workspace-scoped request analysis |
| Analytics users | Per-user cost and usage within the workspace |
| Budgets, Budget detail | Workspace budget assignment and tracking |
| Billing periods, Billing summary | Workspace billing lifecycle and reconciliation |
| Ledger | Workspace-scoped financial ledger entries |
| Outcomes & ROI | Workspace-scoped outcome measurement |
| Budget notifications | Alert coverage for workspace budgets |

## Isolation

Every workspace has its own API keys and data boundary. Switching keys is how scripts and agents switch which workspace receives traffic.
