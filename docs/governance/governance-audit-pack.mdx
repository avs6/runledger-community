The governance audit pack is the evidence view for Safety and Governance. It packages the current governance posture into a single exportable report so operators, auditors, and security teams can answer what happened, which controls fired, and what was retained.

## What the pack includes

| Section | Details |
|---|---|
| Model usage | Which models were used, by whom, and over what period |
| Policy enforcements | Runtime policy actions, including blocked or audited tool activity |
| Approvals | Request type, requester, decision, and timestamp |
| Data capture | Active capture policies and scoped override posture |
| Budget alerts | Budget breaches and governance-related alert activity |

## Identity-scoped evidence

The audit pack supports identity filters so operators can generate evidence scoped to a specific user, access group, or API key:

| Parameter | Description |
|---|---|
| `user_id` | Scope the pack to a single user's activity |
| `access_group_id` | Scope to all members of an access group |
| `api_key_id` | Scope to traffic from a specific API key |

From identity detail pages (Users, Access Groups, API Keys), use the **Governance** link to generate a scoped pack.

## Operator workflow

1. Use date-range and identity filters to choose the evidence window.
2. Review the summary counts and included sections.
3. Pivot into the linked operational owners such as Approvals, Audit Log, Alert Rules, and Data Capture.
4. Export the pack as JSON or CSV for external compliance workflows.

## Why it belongs with the audit log

The audit log is the event stream. The governance audit pack is the reporting bundle built on top of that evidence story. They should be treated as one compliance evidence area rather than two disconnected governance features.
