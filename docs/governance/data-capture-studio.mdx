The data capture policy studio lets org admins decide how much request and response content RunLedger keeps, where scoped exceptions apply, and what the compliance tradeoffs look like before a policy is turned on.

## Capture modes

| Mode | What's stored |
|---|---|
| `METADATA_ONLY` | Token counts, model metadata, timing, and status only |
| `ERRORS_ONLY` | Metadata plus failed-request payload context |
| `SAMPLED` | Full payloads on a configurable sample of traffic |
| `FULL` | Full prompt, response, tool, and payload capture |

## Key features

- **Global policy** - set the default privacy mode for the workspace.
- **Scoped overrides** - create, edit, and delete overrides per org, workspace, API key, model route, user, intent, or agent.
- **Retention preview** - review estimated storage footprint, fields captured, fields redacted, and compliance notes before saving.
- **PII testing sandbox** - paste sample text and inspect detected entities plus the redacted result.
- **Operator-friendly workflow** - the UI now exposes the full scoped-override lifecycle instead of only upsert-style creation.

## Typical flow

1. Start with `METADATA_ONLY` as the baseline.
2. Add a scoped override for a route, API key, or agent that needs deeper debugging.
3. Use the PII sandbox on representative payloads before switching that scope to `SAMPLED` or `FULL`.
4. Remove the scoped override once the investigation window closes.

## Runtime scope and evidence

The Data Capture page includes a Runtime Scope & Evidence posture card (cyan theme) showing how capture policies connect to gateway evidence, observability, budgets, and ledger context:

- **Runtime Posture**: `GET /analytics/data-capture-runtime-posture` returns capture scope (total workspaces, capture policies, active API keys, security events 30d), gateway evidence (provider calls 30d, model routes, cache configs), observe evidence (runs 30d, audit events 30d), budget context (total budgets, budget notifications), and ledger context (ledger snapshots, ledger entries 30d).
- **Drill-Through Links**: Workspaces, API Keys, Model Gateway, Response Cache, Request Flow, Audit Log, Budgets, and Ledger.
- **Stat Tiles**: Provider Calls (30d), Runs (30d), Total Budgets, and Ledger Snapshots.
