---
title: "Replay experiments"
description: "Re-run the captured conversations of recorded runs against other route aliases, through the gateway, and compare quality, cost and latency."
---

Replay is a mode of [experiments](/governance/evaluations#experiments). The old Replay Lab only projected
cost from token counts; replay experiments now send each captured conversation through the gateway again,
once per route alias, and record real responses, cost and latency.

## Workflow

```mermaid
flowchart LR
  runs[Recorded runs with captured payloads] --> ds[POST /datasets/from-runs]
  ds --> exp[Experiment mode=replay, 1..6 route aliases]
  exp --> run[Run through the gateway]
  run --> compare[Per-model score, cost, latency, deltas]
  compare --> rec[Recommend route → Flywheel → apply]
```

- Replays need the original messages, so only runs captured under a `SAMPLED`/`FULL` capture policy can
  be added; others are reported and skipped.
- Set `use_output_as_expected` when curating to score replies against the recorded answer (a regression
  check).
- `/replay` and `/replay/{id}` in the dashboard redirect to `/experiments?mode=replay` and
  `/experiments/{id}`.
