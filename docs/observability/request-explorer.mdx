---
title: "Request Explorer"
description: "Filterable, paginated request investigation surface with run drill-in, route evidence, payload capture, and request-level debugging."
---

The Request Explorer is the request-level drill-down companion to Analytics Overview and Request Flow. It shows individual requests with enough runtime evidence to investigate cost outliers, latency spikes, routing surprises, cache behavior, and unexpected model usage.

## Features

- **Full-text filtering** - narrow by run id, user, model, provider, intent, or optimization markers
- **Status filters** - isolate succeeded, failed, running, or cancelled traffic
- **Pagination** - browse large volumes (configurable page size, max 100)
- **Per-request detail** - inspect prompt/response capture, route hints, model/provider calls, tool calls, spans, outcomes, and gateway evidence
- **Run drill-in** - jump from a request into the dedicated run detail page when you need the full DAG and execution tree
- **Session pivot** - follow the same issue into Sessions when the problem spans multiple turns

## API

```
GET /analytics/request-explorer?q=&status=&end_user_id=&model=&provider=&intent=&optimization=&page=1&page_size=50
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `q` | string | Free-text search over run id, user, model, provider, and related request fields |
| `status` | string | Filter by request/run status (`succeeded`, `failed`, `running`, `cancelled`) |
| `end_user_id` | string | Filter by end user |
| `model` | string | Filter by model name |
| `provider` | string | Filter by provider |
| `intent` | string | Filter by run intent |
| `optimization` | string | Filter by optimization type applied |
| `page` | int | Page number (default: 1) |
| `page_size` | int | Results per page, 1-100 (default: 50) |

Returns `RequestExplorerResponse` with `total_count`, `page`, `page_size`, and `records` array.
