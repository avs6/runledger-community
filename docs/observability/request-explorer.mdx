---
title: "Request Explorer"
description: "Filterable, paginated request investigation surface with run drill-in, route evidence, payload capture, and request-level debugging."
---

The Request Explorer is the request-level drill-down companion to Analytics Overview and Request Flow. It shows individual requests with enough runtime evidence to investigate cost outliers, latency spikes, routing surprises, cache behavior, and unexpected model usage.

## Features

- **Full-text filtering** - narrow by run id, user, model, provider, intent, or optimization markers
- **Status filters** - `succeeded`/`failed` (run words) or `success`/`error`/`timeout`/`blocked`
  (provider-call words); both are mapped to the provider-call status the explorer lists
- **Workflow and intent** - `feature_tag` filters the workflow; `intent` filters the run's intent
  classification. They are separate filters.
- **Model, provider and workflow suggestions** - loaded from `GET /runs/facets`, i.e. what this
  workspace actually recorded in the last 30 days
- **Saved views** - save the current filters per user
- **Errors are shown** - an API failure or a rejected filter shows the error, never an empty list
- **Pagination** - browse large volumes (configurable page size, max 100)
- **Per-request detail** - inspect prompt/response capture, route hints, model/provider calls, tool calls, spans, outcomes, and gateway evidence
- **Run drill-in** - jump from a request into the dedicated run detail page when you need the full DAG and execution tree
- **Session pivot** - follow the same issue into Sessions when the problem spans multiple turns
- **Access-group scope** - pass `access_group_id` to keep the explorer, selected request detail, and run drill-ins inside an Access Group investigation

## API

```
GET /analytics/request-explorer?q=&status=&end_user_id=&model=&provider=&intent=&feature_tag=&api_key_id=&tag=&tool_name=&security_event_only=&optimization=&access_group_id=&page=1&page_size=50
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `q` | string | Free-text search over run id, user, model, provider, and related request fields |
| `status` | string | `succeeded`, `failed`, `success`, `error`, `timeout` or `blocked` (422 on anything else) |
| `end_user_id` | string | Filter by end user |
| `model` | string | Filter by model name |
| `provider` | string | Filter by provider |
| `intent` | string | Filter by run intent |
| `feature_tag` | string | Filter by workflow (feature tag) |
| `api_key_id` | uuid | Calls made with this API key |
| `optimization` | string | Filter by optimization type applied |
| `access_group_id` | uuid | Apply the selected Access Group's investigation profile to the request set |
| `page` | int | Page number (default: 1) |
| `page_size` | int | Results per page, 1-100 (default: 50) |

Returns `RequestExplorerResponse` with `items`, `total`, `page`, and `page_size`.

## Related context

Budgets, billing periods and policies related to a run open on demand in the Related drawer (`GET /context`); the page no longer loads them up front.
