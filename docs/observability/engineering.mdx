The Engineering dashboard is the operator-focused health surface for the request path. It is intentionally investigative rather than CRUD-oriented and is meant to answer:

- Is latency getting worse?
- Are retries or errors rising?
- Is caching helping?
- Which models, tools, and workflows are driving cost?
- Are requests turning into successful outcomes?

## Key metrics

| Card | What it shows |
|------|---------------|
| Avg Latency | Mean response time across all calls |
| P95 Latency | 95th-percentile response time |
| Error Rate | Percentage of calls that returned an error |
| Retry Rate | How often the runtime had to retry |
| Cache Rate | Percentage of calls served from cache |
| Total Requests | Provider calls in the time window |
| Total Tokens | Aggregate token usage |
| Total Cost | Aggregate spend in USD |

## Request lifecycle pipeline

The page visualizes how requests move through the runtime path:

```
Received → Routed → Cached → Completed → With outcome → Positive
```

Each stage shows counts and percentages relative to total traffic in the selected window.

## Cost breakdowns

The shipped page currently breaks engineering cost and activity down by:

- **Feature / workflow area**
- **Model**
- **Tool usage**

## Quality Funnel

Visualizes the drop-off from total requests to positive outcomes:

| Stage | Description |
|-------|-------------|
| Total | All requests received |
| Successful | Requests that completed successfully |
| Routed | Requests that flowed through the gateway runtime |
| Cached | Requests served from response cache |
| With outcome | Requests linked to an outcome event |
| Positive outcome | Requests that ended in a positive business result |

## API

```
GET /analytics/engineering?from=&to=
```

Returns `EngineeringMetrics` with KPIs, lifecycle stages, cost dimensions, and quality funnel in a single response. See the [API reference](http://localhost:8201/reference) for the full schema.
