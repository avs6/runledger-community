Chargeback turns raw AI spend into finance-ready monthly allocation reports that stay aligned to RunLedger's real operating primitives: workspaces, access groups, workflow tags, applications, end users, providers, models, and intent. Export as CSV or JSON, review unallocated buckets, and compare actual spend against budgets where budget scope already aligns.

## Key features

- **Monthly reports** - generate reports for any past month.
- **Modern attribution dimensions** - workspace, access group, workflow tag, application, end user, provider, model, and intent.
- **Rule CRUD** - create, list, edit, and delete chargeback rules directly from the product.
- **Variance vs budget** - line items show actual spend, budgeted amount, and variance when the current budget scope supports it.
- **Unallocated visibility** - unmatched or incomplete attribution stays visible instead of silently disappearing.
- **Export** - CSV and JSON outputs for downstream finance review and evidence packaging.

## Report contents

| Field | Description |
|---|---|
| Dimension label | The entity being charged (access group, workflow tag, application, user, provider, model, intent, or workspace) |
| Total cost | Actual spend for the period |
| Call count | Number of provider calls attributed to the line |
| Run count | Number of runs contributing to the line |
| Budget | Budgeted amount, when a matching budget scope exists |
| Variance | Difference between actual and budget |
| Allocation status | Whether the spend is allocated or still unallocated |
| Coverage status | Whether the line is budgeted or unbudgeted |

## Operator workflow

1. Open `/chargeback`.
2. Create or edit one or more chargeback rules.
3. Choose a period and attribution dimension.
4. Review summary cards for total cost, budget-covered cost, and unallocated cost.
5. Inspect the allocations table for access-group, workflow-tag, application, user, model, or provider rows.
6. Export CSV or JSON for finance review.

## Cohesion notes

- Chargeback is intentionally **workspace-scoped** today, but one supported report dimension is now **access_group**.
- Access-group attribution is derived from access-group membership joined to provider-call `end_user_id`, so caller identity quality still matters.
- **API-key-native** allocation is still a later FinOps deepening pass, not a reason to reopen legacy team or project concepts.

## Chargeback × Cross-Feature Posture Bridge

The chargeback cross-feature posture endpoint surfaces org, gateway, safety, and platform context alongside allocation data so operators can see the full scope of infrastructure and access that drives chargeback attribution.

```
GET /analytics/chargeback-cross-feature-posture
```

Returns org context (users, access groups, API keys, telemetry batches, hub models), gateway context (routes, providers, cache configs), safety context (MCP servers, tool registry, audit events, tags), platform context (organizations, chargeback rules), and 30-day spend.

This endpoint powers the emerald **Chargeback × Cross-Feature Context** card on the Chargeback page with drill-through links to Organization, Access Groups, API Keys, Telemetry, AI Hub, Gateway, MCP Servers, Tool Registry, Audit Log, Tags, and Platform Settings.

## Chargeback Attribution Posture Bridge

```
GET /analytics/chargeback-attribution-posture
```

Returns identity context (workspace users, API keys, access groups), runtime context (cache configs, cache savings, chargeback rules), monitoring context (alert rules, audit events, tags), optimization context (chargeback rules, cache savings), and 30-day spend.

This endpoint powers the emerald **Chargeback Attribution Context** card on the Chargeback page with drill-through links to Users, API Keys, Access Groups, Gateway, Monitoring, Audit Log, Tags, and Optimization.
