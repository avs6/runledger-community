The Billing area is the finance-facing companion to observability and FinOps. It now combines three related operational surfaces in one place:

- **Billing periods** - managed periods that can be opened, closed, exported, and reconciled
- **Billing summary** - rollup view for billable versus non-billable usage across recent periods
- **Shared-cost policies** - workspace-owned policies for allocating overhead before downstream chargeback and ledger close

## Billing summary

The summary view inside Billing shows:

- total cost
- billable versus non-billable split
- total calls
- period-by-period bars
- CSV and JSON export

This summary used to be reachable as a separate top-level page, but it now lives inside Billing so finance workflows stay together.

## Billing periods

Use the periods view when you need:

- period lifecycle management
- close-period actions
- per-period reconciliation status
- detailed application and user breakdown per period
- access-group-scoped period filtering when attribution can be derived from member traffic
- billing-adjustment lifecycle for credits, refunds, prepaid deductions, and surcharges
- export per-period CSV or signed JSON evidence

## Billing detail

Open a billing period when you need to:

- inspect gross versus net cost
- review reconciliation issues and warnings
- manage adjustments before close
- review which adjustments are already reflected in net cost
- export finance evidence for downstream workflows

The billing detail page now includes:

- **Summary** - period metadata, status, and readiness posture
- **Reconciliation** - provider-call versus metering comparison, issues, and warnings
- **Breakdown** - application and end-user allocation view
- **Adjustments** - create, edit, and delete finance adjustments while a period is open
- **Exports** - CSV and signed JSON output

## Access-group scope

Billing now supports access-group-aware review flows:

- `/billing?access_group_id=...` filters the periods table to periods with attributable access-group traffic.
- billing period detail, reconciliation, breakdown, and exports can all stay scoped to that same access group
- this attribution is derived from access-group membership and provider-call `end_user_id` matching, so the scoped view is strongest where caller identity is present and clean

## Shared costs

Use the shared-costs tab when you need to:

- define how overhead should be split before chargeback
- preview allocation outcomes against a cost pool
- maintain active and inactive policy states
- prepare a period for cleaner downstream allocation and compliance closure
