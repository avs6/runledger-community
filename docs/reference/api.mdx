Everything the dashboard and SDKs do is a REST call. The full, always-current API surface is available
interactively on your running instance.

## Interactive reference (current state)

As of **Friday, August 14, 2026**, every RunLedger control-plane instance serves a live, interactive API reference generated from the OpenAPI spec using **Scalar**:

```
http://localhost:8201/reference
```

Try requests directly from the browser with your workspace API key. The raw spec is at
`http://localhost:8201/openapi.json`.

The live gateway data plane is separate:

```text
http://localhost:8210/gateway/chat/completions
```

Use the control plane for route, policy, stats, and operator APIs; use the Rust gateway for live OpenAI-compatible completions traffic.

## Planned API explorer direction

The long-term product direction is to make the OpenAPI spec the single source for:

- the live browser-based API explorer
- any future Swagger-style or embedded API GUI
- downstream generated artifacts

That means the spec remains the durable contract even if the presentation layer changes away from today's Scalar UI.

## Postman

A generated Postman collection + environment live in the repo under
[`postman/`](https://github.com/avs6/runledger-community/tree/master/postman) — import both, set `base_url`
and `api_key`, and every endpoint (including the optimization microservices) is ready to call.

To regenerate the collection after changing the API, run the generator against your live OpenAPI spec:

```bash
curl -s http://localhost:8201/openapi.json -o /tmp/openapi.json
python scripts/generate_postman.py /tmp/openapi.json \
  postman/RunLedger.postman_collection.json \
  postman/RunLedger.postman_environment.json
```

## Authentication

Control-plane endpoints use the API host:

```bash
curl http://localhost:8201/gateway/stats \
  -H "Authorization: Bearer rl_..."
```

Live gateway completions use the Rust data-plane host:

```bash
curl http://localhost:8210/gateway/chat/completions \
  -H "Authorization: Bearer rl_..." \
  -H "Content-Type: application/json" \
  -d '{"model":"chat","messages":[{"role":"user","content":"hello"}]}'
```

Create workspace API keys from **Control Plane -> API Keys** in the dashboard. Org admins and org managers can mint keys for any workspace in their org; workspace admins can mint keys for their active workspace. `POST /auth/login` returns a dashboard session key, not a long-lived agent key.

## Surface at a glance

| Area | Prefix |
|---|---|
| Ingest / runs | `/ingest` · `/runs` · `/sessions` |
| Gateway | Control plane: `/gateway/routes`, `/gateway/stats`, `/gateway/requests`, `/gateway/flywheel` ? Data plane: Rust `/gateway/chat/completions` |
| FinOps | `/budgets` · `/outcomes` · `/ledger` · `/analytics` |
| Quality | `/evaluations` · `/scores` · `/prompts` · `/approvals` |
| Agentic | `/agents` · `/workflows` · `/vector-stores` · `/playground` |
| Admin | `/auth` · `/org` · `/users` · `/settings` · `/retention` |
