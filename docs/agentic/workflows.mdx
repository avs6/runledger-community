title: "Workflow Runs & Steps"
description: "Define multi-step agent workflows, track runs with per-step cost attribution, and monitor execution in real time."
---

RunLedger Workflows model the multi-step execution plans your agents follow. Define a
workflow template once, then track every execution as a **run** with fine-grained per-step
cost and latency attribution.

## Create a workflow

```bash
curl -X POST http://localhost:8201/workflows \
  -H "Authorization: Bearer rl_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "customer-support-pipeline",
    "description": "Triage → research → draft → review",
    "steps_schema": [
      {"name": "triage", "type": "agent", "model": "gpt-4o-mini"},
      {"name": "research", "type": "tool", "tool": "search-api"},
      {"name": "draft", "type": "agent", "model": "gpt-4o"},
      {"name": "review", "type": "human"}
    ]
  }'
```

## List & manage workflows

```bash
# list all workflows
curl http://localhost:8201/workflows?status=active \
  -H "Authorization: Bearer rl_..."

# filter by access group or API key identity
curl "http://localhost:8201/workflows?access_group_id={group_id}" \
  -H "Authorization: Bearer rl_..."
curl "http://localhost:8201/workflows?api_key_id={key_id}" \
  -H "Authorization: Bearer rl_..."

# get workflow detail
curl http://localhost:8201/workflows/{workflow_id} \
  -H "Authorization: Bearer rl_..."

# update
curl -X PUT http://localhost:8201/workflows/{workflow_id} \
  -H "Authorization: Bearer rl_..." \
  -d '{"description": "Updated pipeline"}'

# archive
curl -X DELETE http://localhost:8201/workflows/{workflow_id} \
  -H "Authorization: Bearer rl_..."
```

### Identity filters

| Parameter | Type | Description |
|-----------|------|-------------|
| `access_group_id` | UUID | Show workflows with runs from this access group |
| `api_key_id` | UUID | Show workflows with runs from this API key |

The same filters apply to `GET /workflows/{id}/runs` to scope run listings by identity.

## Start a workflow run

Workflow runs carry API-key and access-group identity so results can be attributed and filtered.

```bash
curl -X POST http://localhost:8201/workflows/{workflow_id}/runs \
  -H "Authorization: Bearer rl_..." \
  -d '{
    "agent_id": "...",
    "api_key_id": "...",
    "access_group_id": "...",
    "trigger": "api",
    "input_data": {"ticket_id": "T-1234"}
  }'
```

## Track run progress

```bash
# list runs
curl http://localhost:8201/workflows/{workflow_id}/runs \
  -H "Authorization: Bearer rl_..."

# get run detail (includes steps)
curl http://localhost:8201/workflows/{workflow_id}/runs/{run_id} \
  -H "Authorization: Bearer rl_..."

# update run status
curl -X PUT http://localhost:8201/workflows/{workflow_id}/runs/{run_id} \
  -H "Authorization: Bearer rl_..." \
  -d '{"status": "completed", "total_cost": 0.045}'
```

## Record workflow steps

```bash
# add a step
curl -X POST http://localhost:8201/workflows/runs/{run_id}/steps \
  -H "Authorization: Bearer rl_..." \
  -d '{
    "step_index": 0,
    "name": "triage",
    "step_type": "agent",
    "model": "gpt-4o-mini"
  }'

# update step with results
curl -X PUT http://localhost:8201/workflows/runs/{run_id}/steps/{step_id} \
  -H "Authorization: Bearer rl_..." \
  -d '{"status": "completed", "cost": 0.002, "tokens": 450, "duration_ms": 1200}'
```

Step types: `agent`, `model`, `tool`, `human`, `condition`, `parallel`.

## Cost attribution

```bash
curl http://localhost:8201/workflows/{workflow_id}/cost \
  -H "Authorization: Bearer rl_..."
```

Returns per-step cost breakdown: `total_runs`, `total_cost`, `avg_cost_per_run`, and
`cost_by_step` (each step's total cost, average cost, and invocation count).

## Cross-Feature Context (Workflow Detail)

The Workflow detail page now displays four cross-feature posture cards for a complete
operational picture:

- **Organization & Access Context** (blue) — workspace, access groups, API keys, hub models.
  Drill-through to Organization, Access Groups, API Keys, AI Hub.
- **Gateway & Routing Context** (violet) — providers, active routes, guardrail rules, cache
  configs. Drill-through to Provider Profiles, Guardrails, Response Cache, Rate Limits.
- **Observe & Analytics Context** (cyan) — runs, provider calls, distinct models, 30-day cost.
  Drill-through to Analytics Overview, Request Explorer, Model Usage, Cost & Savings.
- **FinOps & Budget Context** (emerald) — active budgets, billing periods, budget limit,
  30-day spend. Drill-through to Budgets, Billing Periods.

```bash

  -H "Authorization: Bearer rl_..."
```

The **Workflows** page shows all workflow definitions with run counts, costs, and status.
