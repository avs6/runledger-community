RunLedger's Agent Registry is the identity layer for your AI agents. Every agent that touches
the gateway gets a record — name, type, owner, default model, budget envelope, and config.
Once registered, agents automatically accumulate run stats, cost attribution, and memory.

## Register an agent

```bash
curl -X POST http://localhost:8201/agents \
  -H "Authorization: Bearer rl_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "support-triage",
    "agent_type": "autonomous",
    "default_model": "gpt-4o",
    "budget_envelope": 50.00,
    "owner": "platform-team"
  }'
```

Fields: `name` (required), `description`, `agent_type` (`autonomous | semi_autonomous | workflow | chat`),
`owner`, `default_model`, `default_tools`, `budget_envelope`, `allowed_aliases`, `status`, `config`.
Every entry in `allowed_aliases` must be an existing gateway route alias (422 otherwise).
The old free-text `policy_profile` field was removed because nothing enforced it; its
values were kept in `config.policy_profile_legacy`.

## List & filter

```bash
# all active agents
curl http://localhost:8201/agents?status=active \
  -H "Authorization: Bearer rl_..."

# search by name, or agents with runs sent by an API key
curl "http://localhost:8201/agents?q=triage" \
  -H "Authorization: Bearer rl_..."
curl "http://localhost:8201/agents?api_key_id={key_id}" \
  -H "Authorization: Bearer rl_..."

# single agent detail
curl http://localhost:8201/agents/{agent_id} \
  -H "Authorization: Bearer rl_..."
```

### Identity filters

| Parameter | Type | Description |
|-----------|------|-------------|
| `q` | string | Name contains |
| `api_key_id` | UUID | Agents with runs sent by this API key |

`GET /agents/{id}/runs` takes `status`, `workflow_id` and `api_key_id`.

## How runs are attributed to an agent

Runs carry `agent_runs.agent_id`, resolved at ingest inside your workspace from
`agent_id` / `agent_name` on `run_start` (the SDK's `agent=` / `agent_id=`), or the OTLP
attributes `runledger.agent.id`, `runledger.agent` and `gen_ai.agent.name`. Names match a
non-retired agent exactly; ids from another workspace are ignored.

## Agent stats

```bash
curl http://localhost:8201/agents/{agent_id}/stats \
  -H "Authorization: Bearer rl_..."
```

Computed from the runs attributed to the agent (optionally `?days=`): `total_runs`,
`completed_runs`, `failed_runs`, `total_cost`, `total_tokens`, `avg_duration_ms`,
`success_rate`, `last_run_at`, `models_used` (from provider calls), `tools_used` (from tool
calls) and `envelope`.

## Runtime policy

Each agent's controls are enforced wherever its traffic starts:

| Control | Refused when | Gateway response |
|---|---|---|
| `status` | the agent is `paused` or `retired` | 403 |
| `allowed_aliases` | the request calls an alias not in the list (empty = any) | 403 |
| `budget_envelope` | this month's attributed spend has reached the envelope | 429, `X-Cost-Cap-Reason: agent_envelope` |

Every refusal carries `X-Agent-Policy-Reason` (`agent_inactive`, `alias_not_allowed` or
`envelope_exhausted`).

- **Gateway:** the preflight checks every request whose metadata names a registered agent
  (`runledger.agent`, `gen_ai.agent.name`, `agent_name`, or `runledger.agent.id` /
  `agent_id`), after budgets and before routing. Names prefer an active agent but also find
  paused and retired ones, so those are refused rather than let through.
- **SDK:** `@rl.workflow(..., agent_id=...)` and `rl.task(..., agent_id=...)` call
  `GET /agents/{id}/preflight` first and raise `RunLedgerBudgetExceededError` on refusal.
- **API:** `GET /agents/{id}/preflight?alias=smart` returns the same decision:
  `allowed`, `reason_code`, `reason`, `envelope_usd`, `spent_usd`, `remaining_usd` and
  `allowed_aliases`.

## Agent runs

```bash
curl http://localhost:8201/agents/{agent_id}/runs \
  -H "Authorization: Bearer rl_..."
```

Lists all workflow runs associated with the agent, with pagination.

## Retire an agent

```bash
curl -X DELETE http://localhost:8201/agents/{agent_id} \
  -H "Authorization: Bearer rl_..."
```

Soft-deletes by setting `status = retired`.

## Agent Memory

Each agent has a key-value memory store with PII detection, retention policies, and a full
audit log. Memory is workspace-scoped — agents in different workspaces are isolated.

### Store a memory

```bash
curl -X POST http://localhost:8201/agents/{agent_id}/memory \
  -H "Authorization: Bearer rl_..." \
  -H "Content-Type: application/json" \
  -d '{
    "key": "user_preferences",
    "value": "{\"theme\": \"dark\", \"lang\": \"en\"}",
    "memory_type": "long_term",
    "retention_days": 90
  }'
```

RunLedger automatically scans the value for PII patterns (emails, phone numbers, SSNs,
credit cards, IP addresses). If detected, the memory is flagged `has_pii = true` and an
audit event is logged.

### List & search memories

```bash
# list all
curl http://localhost:8201/agents/{agent_id}/memory \
  -H "Authorization: Bearer rl_..."

# full-text search
curl -X POST http://localhost:8201/agents/{agent_id}/memory/search \
  -H "Authorization: Bearer rl_..." \
  -d '{"query": "preferences", "limit": 10}'
```

### Memory stats

```bash
curl http://localhost:8201/agents/{agent_id}/memory/stats \
  -H "Authorization: Bearer rl_..."
```

Returns `total_memories`, `total_size_bytes`, `by_type` breakdown, `pii_count`,
`expired_count`, and the `most_accessed` memories.

### Audit log

```bash
curl http://localhost:8201/agents/{agent_id}/memory/audit \
  -H "Authorization: Bearer rl_..."
```

Every store, update, delete, and PII detection event is logged with timestamp, actor, and details.

## Dashboard

The **Agents** page in the dashboard shows a card grid of all registered agents with type
badges, status indicators, model info, run counts, and cost totals. Click through to the
agent detail page which links to runs and memory.

The **Memory** sub-page shows stat cards, a searchable memory table with PII flags, access
counts, and retention info, plus the audit log.
