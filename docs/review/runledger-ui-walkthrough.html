Technical due diligence · Pass 3 · Live UI walkthrough

Every page, tab and filter, checked against the code

I signed in to the home-lab deployment as HomeLab Admin (workspace AgentTest, role WS Admin) and walked every side-nav item, every expandable sub-item, every in-page tab and every reachable sub-page. For each one I recorded headings, tabs, filters, tables, pagination, empty and error states and outgoing links, then checked what I saw against the page and API source. The UI is visually polished and broad. The recurring problems are broken cross-links, read-only screens over full CRUD backends, hard-coded option lists, missing pagination and sorting, and controls whose backend is decorative.

Biggest UX themes. (1) The app links to routes that don't exist: /telemetry, /governance, /audit-log, /workspaces, /admin/*, /analytics/* and more. (2) Backends with full CRUD are exposed read-only: Workflows have no create, edit or delete; Agents have no edit or delete; OAuth2/LDAP aren't on the Security page. (3) Pagination is inconsistent: four styles, and none on Routes, API Keys, Alert Rules, Scores or Approvals. (4) The UI offers actions the role or backend can't perform: per-key quota tiers, per-model quotas, Throttle/Fallback budget actions, partner guardrails, demo reset for non-platform admins, and the Ledger link. Resolved: demo controls shown to platform admins only

  • Hybrid pagination: the client pages 20 at a time over a 50-row server page (RunsPaginated.tsx:8-27). On the last page a full-page link "Load more from server" replaces the list with the next cursor page. There's no going back except the browser, and the "x of 50 loaded (61 total)" wording is confusing.
  • The filter panel is good but exposes API key ID as a raw UUID text box. There's no access-group filter (the API supports access_group_id) and no workflow filter. There's no prompt/response panel here, although Request Explorer has one for the same run. No "replay this run" or "add to dataset" action exists.

Onboarding

Method

  • Driven in the owner's Chrome via Claude in Chrome, signed in as HomeLab Admin (WS Admin, workspace AgentTest). No create, update or delete actions were performed; only tabs and pagination controls were clicked.
  • For each page, a read-only DOM extractor recorded headings, tabs, selects, inputs, buttons, tables (headers + row counts), pagination text, empty/error strings, toasts and outgoing in-app links. Links were then fetched in the signed-in session to classify them as 200, redirect or 404.
  • Findings were cross-checked against apps/web (page components, lib/api.ts) and apps/api (routers and services). File references point to the working tree at review time.
  • Pages requiring platform admin (Settings, Global Dashboard, All Organizations) were observed only as their access-denied or redirect state.
  • Corrections to earlier passes found during this walk: Runs does have a status filter and a "Load more from server" link; required-metadata reject mode works; rate limits, response cache, budget tiers and model budgets are tabs inside Model Gateway rather than orphan pages.
